# テスト仕様書

## 1. 単体テスト (Unit Test)

| ID | テスト項目 | 入力値・条件 | 期待される結果 |
|:---|:---|:---|:---|
| UT-01-01 | TODO生成の妥当性 | タイトル="Task1", 期限=将来の日時 | 各属性が正しくセットされたTaskインスタンスが返る |
| UT-01-02 | タイトルバリデーション | タイトル=空文字 | `IllegalArgumentException` 等のバリデーションエラーが発生する |
| UT-01-03 | 期限バリデーション | 期限=過去の日時 | バリデーションエラーが発生する |
| UT-02-01 | ステータス更新 | 完了メソッドを呼び出す | ステータスが「DONE」に変更され、完了日時が記録される |

## 2. 結合テスト (Integration Test)

| ID | テスト項目 | 入力値・条件 | 期待される結果 |
|:---|:---|:---|:---|
| IT-01-01 | SQLite保存 | 任意のTaskオブジェクト | `task`テーブルに1レコード追加されること |
| IT-01-02 | SQLite取得 | 存在するIDを指定 | 指定したIDの内容と合致するTaskオブジェクトが取得できること |
| IT-01-03 | 一括削除実行 | 完了済み2件、未完了1件が存在 | 完了済みの2件のみが削除され、未完了の1件が残ること |

## 3. システムテスト (System Test)

| ID | シナリオ | 手順 | 期待される結果 |
|:---|:---|:---|:---|
| ST-01-01 | 基本CRUDフロー | 1.作成 -> 2.一覧表示 -> 3.編集 -> 4.削除 | 全ての操作が完了メッセージと共に正常終了し、最終的に一覧が空になること |
| ST-02-01 | 日本語対応 | タイトルに「日本語テスト」と入力して保存 | 一覧表示時に「日本語テスト」と正しく表示されること |
| ST-03-01 | ソート機能(期限) | 期限の異なる3つのタスクを登録し、期限昇順ソートを選択 | 期限が古いものから順に並んで表示されること |
| ST-03-02 | フィルタ(ステータス) | 完了と未完了が混在する状態で「未完了のみ」を選択 | 未完了のタスクのみが表示されること |
| ST-04-01 | 検索機能(部分一致) | タイトル「Java学習」「Python学習」がある状態で「Java」で検索 | 「Java学習」のみが表示されること |
| ST-05-01 | 異常系：不正なID | 編集時に存在しないID「999」を入力 | 「指定されたIDは見つかりません」等のエラーが表示され、メニューに戻ること |
