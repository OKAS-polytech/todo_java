# 運用・保守計画書

## 1. 目的
本ドキュメントは、TODOリストアプリケーションの安定稼働を維持し、将来的な機能拡張や不具合修正を円滑に行うための運用・保守方針を定義する。

## 2. 運用体制
- **運用管理者**: 本システムの稼働状況を監視し、バックアップ等の定常作業を行う。
- **保守担当者**: プログラムの不具合修正、セキュリティアップデート、機能追加を担当する。

## 3. 運用プロセス
### 3.1. バックアップ計画
- **対象**: `todo.db` (SQLiteデータベースファイル)
- **頻度**: 1日1回（深夜帯を推奨）
- **手法**: ファイルコピーによる物理バックアップ。直近7世代を保持する。

### 3.2. 稼働監視
- CUIアプリケーションのため、実行時のログ出力（標準エラー出力）を監視し、致命的なエラーが発生していないかを確認する。

## 4. 保守プロセス
### 4.1. 不具合対応（インシデント管理）
1. ユーザーまたは運用者からの不具合報告を受付。
2. 現象再現確認と原因調査。
3. 修正プログラムの作成および単体・結合テストの実施。
4. 修正版のリリース。

### 4.2. 機能拡張・改善
- **将来的な拡張 (ver2)**: 要求分析段階で挙がっている「ユーザーログイン機能」「ユーザー間共有機能」の追加検討。
- **技術的負債の解消**: 定期的なライブラリ（JUnit, SQLite JDBC等）のバージョンアップ。

### 4.3. 変更管理
- 全てのソースコード修正は、Git等のバージョン管理システムを用いて履歴を管理する。
- 修正内容は `doc/` 配下の関連ドキュメント（設計書等）に反映し、常に最新の状態を維持する。

## 5. 障害時対応
- **DB破損時**: 最新のバックアップファイルから `todo.db` をリストアする。
- **アプリケーション異常終了時**: スタックトレースを確認し、メモリ不足やファイルアクセス権限の問題を調査する。

## 6. 判定基準
- 本計画書に基づき、年1回の運用・保守状況の棚卸しを行い、必要に応じて計画を見直す。
