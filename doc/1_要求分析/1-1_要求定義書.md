# 要求定義書

## 1. 概要
本プロジェクトでは、Javaを用いたCUIベースのTODOリストアプリケーションを開発する。ヘキサゴナルアーキテクチャを採用し、将来的なUIの変更（API化など）やデータベースの変更に柔軟に対応できる設計とする。

## 2. 目的
- 日々のタスク（TODO）を効率的に管理する。
- 拡張性の高いアーキテクチャの導入により、メンテナンス性とテスト容易性を確保する。
- 将来的なマルチユーザー化やWeb UI化に向けたプロトタイプとする。

## 3. 機能要件
### 3.1. 基本機能 (CRUD)
- **TODOの作成**: タスクのタイトル、内容、期限、優先度を入力して保存できる。
- **TODOの参照**: 保存されているタスクの一覧を表示できる。
- **TODOの更新**: 既存タスクの各属性（タイトル、内容、期限、優先度、ステータス）を編集できる。
- **TODOの削除**: 指定したタスクを削除できる。

### 3.2. 検索・整理機能
- **ソート機能**: 作成日時、期限、優先度に基づいて一覧を並び替えられる。
- **フィルタ機能**: 優先度、ステータス（未完了/完了）に基づいて表示対象を絞り込める。
- **キーワード検索**: タイトルまたは内容を対象とした部分一致検索ができる。
- **一括削除**: 完了済みのタスクをまとめて削除できる。

### 3.3. 管理項目（属性）
- ID（一意の識別子）
- タイトル
- 内容
- 期限
- 優先度（高・中・低など）
- ステータス（未完了・完了など）
- 作成日時

## 4. 非機能要件
### 4.1. 技術スタック
- 言語: Java
- アーキテクチャ: ヘキサゴナルアーキテクチャ
- データベース: SQLite (プロトタイプ用)
- ユーザーインターフェース: CUI (コンソール)

### 4.2. ユーザビリティ
- 日本語入出力への対応（全角文字の保存・表示）。
- わかりやすいエラーメッセージの表示。

### 4.3. 拡張性
- 将来的なユーザーログイン機能、ユーザー間でのTODO確認機能の追加が容易な設計とする。

### 4.4. 保守性・テスト
- 永続化層やUI層がビジネスロジックに依存しないようにし、単体テストを容易にする。
